# Оценка моделей по golden set

`evaluate.py` сравнивает готовые предсказания одной модели с эталоном. Требуется Python 3.10 или новее, дополнительных библиотек нет. Скрипт не запускает модели и не изменяет изображения или эталон.

Предсказания трёх обязательных моделей и дополнительной YOLO-Worldv2-S нужно получить через `predict.py`; установка и команды описаны в [MODELS.md](MODELS.md).

## Запуск

Из корня рабочей папки:

```bash
python3 evaluate.py \
  --predictions predictions/dino.jsonl \
  --manifest images_manifest.json \
  --name grounding_dino_tiny \
  --output results/dino.json
```

Команда пересчитывает существующие предсказания DINO. Для OWLv2 и YOLO-World повторите её со своими файлами и названиями.

По умолчанию используется `golden_set.jsonl` рядом со скриптом, независимо от текущего каталога. Другой эталон задаётся через `--golden path/to/golden.jsonl`. Параметр `--manifest` необязателен: без него будут общие метрики, но не разбивка по группам. Остальные относительные пути считаются от текущего каталога.

`--output` сохраняет подробный JSON-отчёт и заменяет предыдущий отчёт по этому пути. Без него результат выводится только в терминал. Пороги по умолчанию — 0.5 и 0.75; изменить их можно через `--iou-thresholds 0.5 0.75 0.9`.

## Входной JSONL

Одна строка — одна фотография. Пример формата:

```jsonl
{"photo_id":123,"boxes":[{"left":0.1,"top":0.2,"width":0.3,"height":0.4}],"error":null,"elapsed_seconds":0.82}
{"photo_id":124,"boxes":[],"error":null,"elapsed_seconds":0.75}
```

Координаты нормированы относительно исходного изображения: `left` и `top` — левый верхний угол, `width` и `height` — размеры рамки. Для нескольких бабочек список содержит несколько рамок. `[]` означает успешно обработанное изображение без найденных объектов. Дополнительные метаданные, включая поля существующего `golden_set.jsonl`, разрешены. Если в рамках есть confidence, он не влияет на оценку: фильтрация и удаление дублей должны быть частью зафиксированной конфигурации модели до сохранения предсказаний.

Скрипт предполагает, что входные данные уже корректны: файлы содержат одинаковые уникальные `photo_id`, рамки имеют положительную площадь и находятся в `[0, 1]`, ошибок обработки нет. Порядок строк не важен. Проверки формата, координат, ID и статусов не выполняются; координаты используются как переданы. Пороги IoU также предполагаются корректными: непустой список разных чисел в `(0, 1]`.

## Метрики

Для каждого порога строится отдельное максимальное паросочетание: максимальное число пар «предсказанная рамка — эталонная рамка» с `IoU ≥ порога`. Каждая рамка входит максимум в одну пару. Алгоритм может пересмотреть прежнее сопоставление; он не выбирает просто самые большие IoU по очереди и не максимизирует сумму IoU.

Сначала TP, FP, FN суммируются по всему набору, затем рассчитываются:

- `precision = TP / (TP + FP)`;
- `recall = TP / (TP + FN)`;
- `f1 = 2 × TP / (2 × TP + FP + FN)`.

Правильные пустые ответы не добавляют TP. Если знаменатель равен нулю, метрика записывается как `null` (в терминале — `—`). Например, F1 для группы, в которой нет ни эталонных, ни предсказанных объектов, не определён. Качество на отрицательных примерах показывают отдельные показатели ложных срабатываний.

Отчёт содержит:

- `overall` — общие показатели для каждого IoU: TP/FP/FN, precision/recall/F1, число ошибок объектов `FP + FN`, число фотографий с ошибками;
- `by_group` — те же показатели по полю `group` из manifest; наличие бабочек всегда определяется эталоном, а не названием группы;
- `negative_images`, `false_positive_boxes_on_negatives`, `false_positive_images_on_negatives`, `false_positive_image_rate_on_negatives` внутри каждого блока метрик — число отрицательных изображений, лишних рамок, изображений с ложными срабатываниями и их доля среди отрицательных;
- `per_image` — сопоставленные пары с IoU и индексы несопоставленных рамок; индексы начинаются с нуля и относятся к исходным спискам `boxes`;
- `inputs` — пути и SHA-256 входных файлов для воспроизводимости;
- `timing` — статистика необязательного поля `elapsed_seconds` в предсказаниях. При частичном заполнении `complete=false`, сумма и среднее относятся только к записанным временам. Это время работы модели, указанное при её запуске, а не время работы оценщика. Определение измеряемого интервала следует сохранить в настройках эксперимента.

После `predict.py --retry-errors` поле `elapsed_seconds` у повторно обработанного фото включает время всех его попыток, в том числе неуспешных. Время каждой отдельной попытки сохраняется в `.attempts.jsonl`; загрузка модели и скачивание изображений в эту сумму не входят.

Прогнозы не сортируются по confidence и не фильтруются. Повторные рамки не удаляются: несопоставленные дубли увеличивают FP.
